# 구조와 데이터 설계 방향

세부 구현을 탐색하는 [공개 인터랙티브 설계도](https://pds-diary-architecture-06-m2021.happybay512.chatgpt.site)는 로그인 없이 바로 열 수 있습니다. 요소에 마우스를 올리거나 키보드로 포커스를 옮기면 직접 연결된 개념과 선을 강조합니다. 클릭·터치하면 선택이 유지되며 작은 화면에서는 노드가 재배치됩니다. 구현 구조, 데이터 관계, 명령·규칙, 검증·운영의 네 관점을 제공합니다. 하단에는 전체 변경 명령, 모든 테이블 필드·제약, 소스별 import/export와 테스트 항목을 포함합니다. [오프라인 HTML](architecture-diagram.html)도 제공합니다.

설계 원본은 [JavaScript 모델](architecture-model.mjs)과 [다이어그램 템플릿](architecture-diagram.template.html)입니다. `node scripts/build-architecture.mjs`로 DB 계약·현재 추적 소스 목록을 다시 읽어 브라우저에서 바로 열 수 있는 단일 HTML을 생성합니다. 이 명령은 DB나 배포 상태를 변경하지 않습니다. 상단의 커밋은 기준 HEAD이며 작업 폴더의 미커밋 변경도 생성 시 반영됩니다. 코드를 변경한 후 설계 설명은 모델에서 갱신하고 다시 생성해야 합니다. 테이블 세부 정의·명령 목록의 누락·연결 참조·소스 경로는 생성 시 검사합니다.

설계도 전용 Sites ID는 [architecture-hosting.json](architecture-hosting.json)에 보존합니다. `node scripts/build-architecture.mjs --site-dir work/architecture-site`는 별도 사이트의 `dist/index.html`과 호스팅 선언을 준비합니다. 이후 Sites 소스 동기화·버전 저장·배포 단계가 필요하며, 파일 생성만으로 공개 사이트가 갱신되지는 않습니다. 기존 다이어리의 루트 `.openai/hosting.json`과 DB는 별도입니다.

React 19·TypeScript와 Sites 공식 Vinext starter로 구현한 단일 웹 앱입니다. Cloudflare Worker의 API와 D1(SQLite)를 사용하며, Drizzle은 스키마·마이그레이션 생성에 사용합니다. DB 요청은 서버에서 매개변수 SQL과 원자적 batch로 처리합니다.

## 폴더 책임

| 위치                      | 책임                                            |
| ------------------------- | ----------------------------------------------- |
| `src/features/plans`      | 계획, 수정 이력, 변경 비교                      |
| `src/features/tasks`      | 할 일 관리, 검색·필터·정렬, 빠른 추가·삭제 복원 |
| `src/features/executions` | 실행 기록, 타이머, 시간 수정                    |
| `src/features/reviews`    | 돌아보기·근거 이동·차트·다음 계획 연결          |
| `src/features/today`      | 오늘·지연·진행 중 조회 화면                     |
| `src/components/ui`       | 버튼·입력·상태 안내·대화상자 등 공통 UI         |
| `src/shared`              | 공통 타입, 날짜·시간 규칙과 표시 유틸리티       |
| `src/server`              | DB 접근, 트랜잭션, 검증, 서버 전용 설정         |
| `drizzle`                 | 버전별 스키마 변경과 제약                       |
| `contracts`               | 실제 DB와 일치하는 스키마 계약                  |
| `public`                  | 공개 가능한 정적 이미지·아이콘                  |
| `scripts`                 | 반복 가능한 검증·개발 보조 명령                 |

루트 `app/page.tsx`가 클라이언트 다이어리를 열고, `app/api/diary`가 조회·변경을, `app/api/export`가 내보내기를 담당합니다. `worker`와 `scripts/vite`는 Sites 런타임 통합입니다.

## 데이터 관계 초안

- 계획은 여러 할 일과 여러 수정 이력을 가집니다. 수정해도 계획 ID는 유지합니다.
- 할 일은 하나의 계획에 속하며 여러 실행 기록을 가질 수 있습니다.
- 실행 기록은 계획의 예상값과 별도 보존합니다.
- 돌아보기는 대상 기간·계획·개선점과 다음 계획 연결을 서버에 보존합니다. 화면의 수량·시간은 대상 원본 자료로 계산합니다.
- 중복 요청의 식별 정보는 완료 처리 결과와 함께 보존합니다.

실제 테이블은 plans, plan_revisions, tasks, executions, timers, completions, reviews, commands입니다. 최종 정의는 `contracts/pds-schema-v2.json`에 있습니다.

## 구현 기본안

아래는 과제 원문이 세부 방식까지 정하지 않은 부분에 적용한 구현 규칙입니다. 스키마 계약과 검증 사례로 확인합니다.

- 기간 조회는 할 일의 마감일을 기준으로 합니다. 선택된 할 일의 모든 실행 기록을 시간 합계에 포함하고 이 기준을 화면에 표시합니다.
- 마감일·계획 기간은 날짜로 저장합니다. 실행 시각은 UTC로 저장하고 서울 시간으로 표시합니다.
- 소요 시간의 저장·집계 단위는 분입니다. 타이머는 올림해 최소 1분으로 계산하고, 직접 수정한 양의 정수 분을 실제 시간으로 보존합니다.
- 동일 정렬값은 생성 시각과 고유 ID로 순서를 확정합니다.
- 삭제는 논리 삭제를 사용합니다. 삭제한 할 일과 그 실행 기록은 현재 돌아보기에서 제외하며, 복원 시 다시 포함합니다. 전체 내보내기에는 삭제 표시와 보존 이력도 포함합니다.
- 완료 취소는 현재 상태만 바꾸고 과거 실행 기록을 지우지 않습니다.
- 완료 처리에는 요청 식별 키·DB 제약·트랜잭션을 사용합니다. 같은 요청의 재전송과 이미 완료된 항목에 대한 추가 완료 요청은 새 완료 기록을 만들지 않습니다. 완료 취소 후 정당한 재완료는 별도 상태 전이로 처리하고, 완료 수는 현재 상태를 기준으로 합니다.
- 타이머는 경과 초를 계속 더하는 대신 저장한 시작 시각을 기준으로 복구합니다. 서버 저장에 실패하면 저장되지 않았음을 분명히 표시합니다.
- 내보내기는 계획·수정 이력·할 일·실행 기록·돌아보기·개선점 관계, ID, 날짜·단위를 보존하는 단일 JSON 파일을 기본안으로 합니다. 비밀키와 내부 설정은 제외합니다.

최종 DB 계약과 마이그레이션이 다르면 구현 완료로 보지 않습니다.
